# 协作摘要

- 目标：硬切接通六类聊天实体的本地事务 outbox、加密推送与远端 apply，生产不再使用仅本地同步写入器。
- 跟踪：https://github.com/BelovedYaoo/kelivo/issues/50
- 当前：生产聊天内容运行时、配置 Provider、附件双向断点、schema 19、结构化消息附件与附件 HTTP 已接入；消息密文 payload 已硬切 v2 完整附件身份，上层本地路径 marker 已完全移除。
- 已完成：本地业务写、sync intent 与 dirty 收口已改为同一 SQLCipher 事务；异常整体回滚。
- 已完成：CloudSyncProvider 已建立失败关闭的内容运行时合同，运行时初始化成功后才打开内容门；登出与重启会优先关闭内容运行时并始终清理会话/释放工作区租约。
- 已完成：认证与运行时共用设备状态访问，持久会话硬切 schema v3 并绑定设备密钥版本；ARK 租约严格核对账户、设备与世代后仅允许一次所有权转移。
- 已完成：六类聊天实体支持严格快照读取与事务内远端应用；依赖顺序、墓碑顺序、幂等 turn 删除、无 outbox 回声及拉取生命周期均已有回归门禁。
- 已完成：账户记录信封、会话和安全核心统一接受完整正 uint32 keyEpoch，拒绝零与超界值。
- 已完成：持久账户会话提供唯一认证会话转换入口，Provider 配对批准与后续 transport 不再丢失已验证的 deviceKeyVersion。
- 已完成：SQLCipher schema 17 新增严格配置 Vault 与附件上传断点；十类配置实体支持规范 codec、事务远端应用、依赖排序和墓碑，旧数据库 schema 不迁移。
- 已完成：生产聊天内容运行时组装 ARK、记录加密、outbox、pull、聊天适配器与串行调度器；有效会话的 ChatService 不再使用 LocalOnly 写入器。
- 已完成：八个配置 Provider 在账户态从 SQLCipher Vault 水合；本地 Provider、Vault 与 outbox 原子提交并可回滚，远端刷新不产生 outbox 回声，旧 SharedPreferences 不再作为同步配置真源。
- 已完成：安全核心 ABI v8 提供不透明附件密钥、ARK 包装及绑定上传上下文的独立分块加解密；原始 ADK 不进入 Dart。
- 已完成：附件 manifest 使用 ARK 认证的账户记录密文，密文内绑定 attachmentId、uploadId、keyEpoch、完整分块布局、内容摘要、包装 ADK、显示名称和 MIME；外层身份错配、篡改、截断及非法边界均失败关闭。
- 已完成：附件创建、manifest、分块与提交四阶段持久状态机落入 SQLCipher；mutationId、精确待发密文路径、CAS 租约、过期接管与失败重试跨重启保持一致，4 MiB 分块密文不进入数据库或 WAL。
- 已完成：附件 create、put、commit、manifest、chunk、delete 六个强类型 POST 操作接入完整会话令牌；请求与响应严格绑定 attachmentId、uploadId、keyEpoch、分块身份和长度，拒绝额外响应字段及非规范 Base64URL。
- 已完成：消息密文 payload 硬切 v2，附件引用必须包含规范 attachmentId、uploadId、正 uint32 keyEpoch、kind 与 order；旧 v1 和缺失远程身份的旧结构一律拒绝。
- 已完成：单消息密文附件上限固定为 32，编码与解码均在递归复制附件对象图前失败关闭；正式 schema 继续约束连续 order 与远端身份唯一性。
- 已完成：schema 18 持久化上传分块 SHA-256、连续失败与终止原因，并新增完整身份幂等的下载断点、暂存重建、精确 CAS 清理及资产注册原子提交；终止状态保留全部清理凭据。
- 已完成：附件资产 GC 会同步清除已删除本地资产的下载映射；同一内容允许多个远端附件身份复用，schema 17 仍由安装门禁硬切且不迁移。
- 已完成：附件原子文件存储使用账户工作区固定布局、同目录独占临时文件、持久性屏障与无覆盖发布；上传/下载 staging 隔离，最终内容按 SHA-256 寻址，只有单个密文分块允许整体进入内存。
- 已完成：上传 staging 路径硬切绑定分块 mutationId，消除随机 AEAD 密文在“文件发布后、DB 记账前”崩溃后的重建冲突；内容寻址文件支持受限分块读取与全量流式校验。
- 已完成：schema 19 将资产、消息有序附件引用与 GC 状态纳入正式 Drift/SQLCipher 结构；远端身份三元组必须完整，同一消息的 attachmentId/uploadId 不得重复，同一本地资产允许建立多个独立远端上传身份，旧 schema 不迁移且运行时不再动态补表。
- 已完成：下载明文暂存按 attachmentId/uploadId/keyEpoch 隔离为单一 plaintext.part，以数据库确认偏移恢复和截断；发布前流式核对长度与 SHA-256，并以内容摘要原子发布。
- 已完成：附件上传协调器按持久草稿有界推进 create、manifest、chunk 与 commit，支持精确 mutation 重放、租约接管、源文件一次认证和失败关闭。
- 已完成：上传草稿与 `message_asset_rows(revision_id, ordinal)` 建立唯一复合外键；创建前严格核对本地资产与消息元数据，commit 在同一事务内回填远端三元组并完成上传租约 CAS，任一步失败整体回滚。
- 已完成：下载协调器在 pull 事务外按远端步骤预算物化并认证附件，事务内只接受精确 ready 身份；pending 与未来 keyEpoch 均保持整页 checkpoint 不变，空附件也会原子清理旧引用。
- 已完成：`ChatMessage` 持有最多 32 个不可变有序结构化附件，仓储所有消息写入口原子写入资产与引用并批量水合；同步 apply 将 ready 附件直接交给消息仓储，避免先删后写的双事务窗口。
- 已完成：本地发送、临时会话与用户消息编辑已直接构造结构化附件，正文保持纯文本；托管路径、普通文件、流式摘要和 32 项上限均在事务前失败关闭，消息与引用单事务落库。
- 已完成：生产层已移除本地路径 marker 解析、启动回填、沙箱路径迁移及二次 best-effort 引用同步；仓储中无调用的旧迁移/回填 API 与专用测试已删除，不保留旧明文路径兼容入口。
- 已完成：聊天展示、mini map、模型请求与导出均直接消费 `ChatMessage.attachments`；本地旧 marker 仅作为普通文本，远程 HTTP/HTTPS/data 内联图片保持原有语义，导出不泄漏本地绝对路径。
- 已完成：模型请求管线以进程内强类型字段传递结构化附件并在预处理阶段强制移除，不再把本地路径编码为临时正文 marker；字段损坏时失败关闭，附件为空正文仍可正常进入请求。
- 已完成：Android/iOS 云同步页面可切换登录与首设备注册并提交 displayName，桌面端保持只能登录；请求期间禁止重复提交，四份 ARB 与生成本地化已同步。
- 已完成：安全核心 ABI v9 暴露通用 336 字节 ARK 轮换信封 seal/open，完整绑定账户、签发设备、目标设备、公钥与 keyEpoch；ARK 只以不透明句柄存在，失败输出清零并受关闭/并发门禁保护。
- 已完成：同步调度器将不可重试的 unauthenticated/forbidden 提升为单次终止事件，解除在途周期后再通知 Provider；Provider 以会话世代隔离旧回调，先持久清除会话，再关闭 runtime/ARK 并释放工作区租约。
- 已完成：ARK 不透明句柄硬切为最多 8 个严格递增代次的固定密钥环，设备状态硬切 KDST v2 固定 448 字节；历史记录、附件和信封按精确代次选钥，缺失代次失败关闭且不回退当前密钥。
- 已完成：密钥环裁剪使用固定槽原地覆盖并立即清零源槽，不再使用可能遗留秘密副本的 Vec 重分配或 remove；主线复验通过安全核心 18 项及账户工作区/同步协议 216 项测试。
- 已完成：平台无关的 E2EE 单次后台同步运行器统一核算单调总时限、网络步骤和附件密文字节预算；截止或取消会中止并等待在途网络结算，结束后解除取消监听，并按内容运行时、账户租约、工作区租约逆序释放所有权。
- 已完成：后台运行器使用无 UI Provider 的配置桥接和单周期内容运行时；不可重试的 401/403 会先持久清除会话再完整清理资源，构造失败保留首要异常且不会泄漏网络客户端或业务租约。主线定向分析通过，数据库约束与内容门禁 148 项测试通过。
- 已完成：安全核心 ABI v11 新增账户信任根 Ed25519 派生、签名与严格验签；ARK 注册表和 Dart 句柄硬绑定规范 userId，所有密钥环合并、记录、附件、配对和信封路径拒绝跨账户复用，原始 ARK 与派生 seed 不跨 FFI。主线依赖 19 项、根项目四组 282 项测试及两侧静态分析通过。
- 已完成：SQLCipher schema 20 新增每账户唯一的已验证成员清单锚点物理存储，固定完整清单长度、摘要、security generation、完整 uint32 keyEpoch、CAS 版本与时间约束；冻结 schema 仅保留 v20，旧库不迁移。当前仅落物理表，可信写命令等待 `E2eeVerifiedMembership` 私有构造类型接线，不开放裸清单写入口；schema/安装/约束 94 项测试通过。
- 已完成：`kelivo-api/main@02dce9e` 已推送 D1/R2 密文附件六端点、原子配额、幂等状态机及完整 uint32 keyEpoch；未部署。
- 已确认：成员清单必须签名覆盖恢复公钥、恢复胶囊版本与摘要，并在 SQLCipher 持久化最后验证清单锚点；服务器投影只参与 CAS，不能成为信任来源。普通登录使用的会话代必须与签名成员的稳定认证代分离。
- 已确认：恢复介质必须固定 genesis 完整清单；清单显式携带当前信任公钥，并以旧 epoch 过渡签名和当前 epoch 持有签名建立不可伪造的完整历史链，否则恶意服务器可向恢复设备替换为自选 ARK。撤销禁止由被撤销设备自发起；单一恶意服务器仍可隐藏或回放真实旧前缀，但不能构造服务器已知 ARK 的有效后继。
- 已确认：ARK 轮换后必须冻结普通同步并完成全局 data-rekey；记录按精确 epoch 派生 ID，附件拆分分块 epoch 与 manifest epoch，服务端游标绑定 data generation，最终新 snapshot 完成后才可幂等裁剪旧 ARK。保证撤销后的新写前向隔离，不声称让旧设备忘记其已获得的历史明文或密钥。
- 下一步：合并严格安全 API 客户端，实现规范签名成员清单、客户端强验证、本地锚点与原子 ARK 轮换。
- 审计关键路径：移动端首账户注册、二维码/恢复文件、撤销设备后的 ARK keyring/epoch 轮换、后台同步的平台调度与签名安全状态预检、D1 硬重建及 Worker 部署尚未完成。
- 已知边界：结构化附件读写链路已经硬切完成；签名成员清单、撤销后的 ARK 轮换、恢复流程与平台后台调度尚未闭环，因此内容同步仍不能作为完整公开 E2EE 发布。
- 约束：不保留旧数据、旧 payload 或双写兼容路径；业务接线完成并验证前不提前开启内容同步。
